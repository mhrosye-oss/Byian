# تسميع المعلم: نتائج فحص دمج ASR

**الحالة:** لا يتضمن هذا التغيير محرك تفريغ أو مفتاح تبديل. لم يُختبر التعرف الفعلي، ولم يُرسل تسجيل إلى أي خدمة، ولم يُنزَّل نموذج. شاشة التسميع الحالية تسجّل AAC في ملف `.m4a` مؤقت، ثم تستخدم `NoOpAsrEngine` الذي يعلن عدم توفر المحرك دون قراءة الصوت. لا يُعد النص الناتج أو تقييم التجويد متاحًا. ملف التسجيل المؤقت قد يُحذف بواسطة النظام لاحقًا.

## العوائق المثبتة

- `flutter_quran_tajwid` الإصدار 1.0.3 يطلب `record: ^6.1.2`؛ يثبت هذا المشروع `record: 5.0.4` ويستخدم override لـ5.0.4. نجح `flutter pub get` للحزمتين في نسخة تجريبية **فقط مع تجاوز هذا القيد**، وليس ذلك إثباتًا للتوافق. إزالة تعارض الإصدار وترقية التسجيل تتطلب اختبار مساري التسجيل الحاليين على الأجهزة. أمكن حل الاعتماديات في نسخة منفصلة باستخدام `record` 6.2.1، دون اختبار الأجهزة.
- الخدمة الفعلية للحزمة السحابية `services/gemini_live_service.dart` غير مُصدَّرة من واجهة الحزمة الرئيسية، وهي خدمة Live لـPCM خام 16 kHz mono وليست واجهة قبول ملف M4A. الإعداد في المصدر لا يفعّل `input_audio_transcription` ويضبط استجابة TEXT؛ توثيق Google يشترط إعداد التفريغ صراحة. لا تتعامل الخدمة مع تأكيد `setupComplete` قبل إرسال الصوت، ولا تعرض آلية إنهاء إرسال مناسبة للملف في واجهتها. تطبع الرسائل الخام ونصوص التفريغ عبر `debugPrint`، وتضع مفتاح API في عنوان WebSocket. لا يوجد مفتاح أو خادم آمن مهيأ في التطبيق. لا يكفي تغيير امتداد ملف M4A أو تسميته WAV/PCM؛ يلزم فك الترميز، إعادة أخذ العينات وتمرير PCM16 little-endian صحيح. كما يلزم التحقق من نموذج Gemini Live المتاح حاليًا وسياسة الخصوصية وموافقة المستخدم قبل الإرسال. الإعداد الافتراضي في الحزمة `gemini-2.0-flash-exp` غير مثبت الصلاحية في هذا المشروع.
- `whisper_ggml` الإصدار 2.10.0 يتطلب Dart 3.7+، وAndroid API 24، وiOS 15.6؛ المشروع يعلن Dart 3.0+، وAndroid API 23، وiOS 13.0. كما يطلب Android NDK 29.0.13113456 وCMake 3.22.1، بينما التطبيق يحدد NDK 27. يفرض Gradle في الجذر compileSdk 34 على جميع المشاريع، رغم أن Whisper يطلب 36 واعتماد FFmpeg يطلب 35؛ يلزم التحقق من البناء بدل افتراض نجاحه. رفع الحد الأدنى سيحرم الأجهزة الأقدم من النسخة الحالية ويحتاج قرارًا صريحًا.
- يحدد Whisper معماريات Android `armeabi-v7a` و`arm64-v8a` و`x86_64` و`x86`؛ يوثق FFmpeg المرفق هذه المعماريات أيضًا. هذا ليس إثباتًا أن APK الناتج يعمل على كل ABI، وFlutter لا يدعم عمومًا إنشاء تطبيق Android x86 32-bit. يجب اختبار المخرجات الفعلية على الأجهزة/المحاكيات المعنية.
- النموذج متعدد اللغات `ggml-tiny.bin` حجمه 77,691,713 بايت (نحو 74 MiB)، و`ggml-base.bin` حجمه 147,951,465 بايت (نحو 141 MiB)، دون احتساب ذاكرة التشغيل والملفات المؤقتة. لا يوجد نموذج في التطبيق. يجب موافقة المستخدم قبل تنزيله، والتحقق من سلامة التنزيل، وتوضيح المساحة وسياسة الإزالة. لا تُستخدم نماذج `.en` لتفريغ العربية. وثائق الحزمة تذكر نحو 100 MB RAM لـtiny عند الاحتفاظ بالنموذج محمّلًا.
- يستخدم Whisper FFmpeg لتحويل المدخل إلى WAV 16 kHz mono؛ الملف الناتج الإضافي يحتاج تنظيفًا صريحًا بعد الانتهاء، كما أن اعتماد FFmpeg يضيف متطلبات بناء وحجمًا. على Linux وWindows يحتاج التحويل إلى `ffmpeg` في PATH، أو صوت WAV مطابق أصلًا. لا ينبغي إرسال ملف M4A باعتباره WAV أو تمرير ترويسة WAV على أنها PCM خام.

## مسار إكمال مقترح

1. توفير Android SDK وNDK وCMake المناسبين وأجهزة/محاكيات، وتحديد ما إذا كان إسقاط Android 23 وiOS 13–15.5 مقبولًا أو اختيار بنية منفصلة تحافظ على النسخة القديمة. حل تحديث `record` دون فرض نسخة مخالفة، مع اختبارات تسجيل وتشغيل المسارين الحاليين.
2. إتاحة نموذج Whisper متعدد اللغات محليًا بعد موافقة صريحة، والتحقق من وجوده وصلاحيته قبل الاستدعاء، وتمرير مسار التسجيل الفعلي بالعربية. التعامل مع نقص النموذج وفشل فك الصوت والاستدلال، وتنظيف نسخ WAV المؤقتة. لا يُجرى تنزيل صامت.
3. إعداد خادم مفوض أو آلية اعتماد قصيرة العمر وتدقيق خدمة Gemini أو استبدالها/إصلاحها؛ لا تُضمَّن مفاتيح في التطبيق ولا تُسجَّل النصوص الحساسة. لا يُرسل الصوت دون موافقة واضحة مسبقة. يلزم احترام بروتوكول إعداد جلسة Live وإرسال الصوت وإنهائه واستقبال التفريغ النهائي، مع مهلة وأخطاء صريحة.
4. بعد وجود محركين فعليين، يُربط مفتاح التبديل في شاشة النتيجة بالملف المسجل نفسه، وتُزال نتائج المحرك السابق عند التحويل والفشل، وتُختبر الموافقة والملف المفقود والنموذج المفقود والخادم والخطأ والتبديل المتزامن. يُعرض التفريغ على أنه تقريبي، لا حكم قطعي على التجويد أو صحة القرآن.

## الأدلة وإعادة الاختبار

- سجل التشغيل الأصلي في هذه البيئة: `flutter analyze` نجح دون ملاحظات، و`flutter test` نجح في 144 اختبارًا قبل إضافة اختبار عدم توفر المحرك؛ اختبار الوحدة المضاف يفحص تصريح عدم توفر محرك NoOp فقط، ولا يختبر Whisper أو Gemini.
- `flutter build apk --debug --no-pub` فشل برسالة `No Android SDK found`. لم يتم إثبات صلاحية بناء Android، سواء قبل أو بعد أي دمج.
- وثائق الحزم: [flutter_quran_tajwid 1.0.3](https://pub.dev/packages/flutter_quran_tajwid/versions/1.0.3)، [whisper_ggml 2.10.0](https://pub.dev/packages/whisper_ggml/versions/2.10.0)، [Google Live API](https://ai.google.dev/gemini-api/docs/live-guide). فُحص أيضًا محتوى أرشيفَي الحزمتين المنشورين فعليًا، وليس README وحده. أحجام النماذج من `x-linked-size` في [tiny](https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-tiny.bin) و[base](https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.bin).
